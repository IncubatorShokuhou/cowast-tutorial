# COAWST compile and run guide

[中文](user-guide.zh-CN.md) · [Home](../README.md) · [中文首页](../README.zh-CN.md)

**COAWST** (Coupled-Ocean-Atmosphere-Wave-Sediment Transport Modeling System) couples ROMS, SWAN/WW3, and optionally WRF into a single executable through MCT. Building it requires one shared Fortran / MPI / NetCDF toolchain aligned with MCT. At run time, `mpirun -np` must equal the sum of the `Nnodes*` values in `coupling_*.in`. This guide documents compiling and short-running **INLET_TEST** (ROMS+SWAN) and **JOE_TC Coupled** (WRF+ROMS+SWAN) on Linux with COAWST v3.9. Standalone WRF build and run steps are not repeated here.

> **Note**
>
> Spoken names cowast / COWAST refer to the same USGS system; the official spelling is **COAWST**. The license is USGS public domain / CC0 1.0. The standard ROMS–SWAN–WRF–WW3 path does not depend on proprietary libraries.

## 1. Getting started

The source tree is **COAWST v3.9** from `https://github.com/DOI-USGS/COAWST.git`, commit `81df2ed` (full hash `81df2edcd175fb87426b4d913f4fdaa42cfc50ad`). Coupled cases are driven by `build_coawst.sh` at the repository root: the script reads the application header to decide which models to enable, then builds MCT parameters, optional WRF/WW3, SWAN, and the ROMS driver in order. Do not compile WRF alone with `./compile em_real` for a coupled application. The tree also contains the user manual `COAWST_User_Manual.docx` and the directories ROMS, WRF, WPS, SWAN, WW3, InWave, Master, Lib, Compilers, and Projects. **Sandy** and **JOE_TC DiffGrid** were not built on the verification host used for this guide.

```bash
cd /workspace
git clone --depth 1 https://github.com/DOI-USGS/COAWST.git
# Result: /workspace/COAWST (about 1.8G), commit 81df2ed
```

The GitHub clone works; the alternate URL is `https://code.usgs.gov/coawstmodel/COAWST`.

## 2. Prerequisites

COAWST links several Fortran models into one `coawstM`. NetCDF, MPI, and MCT must be built with the same `mpicc` / `mpif90`; mixing compilers produces errors such as “module file was not generated by this compiler” or a missing `m_MCTWorld`. Required components are gfortran, C/C++, OpenMPI, NetCDF-C and NetCDF-Fortran (NetCDF4), HDF5, cmake, make, perl, git, and the bundled **MCT** under `Lib/MCT` (build it first). Applications that include WRF also need m4, flex, bison, and `/bin/csh`.

gfortran 7 or newer is recommended: `Linux-gfortran.mk` errors on gfortran 6 and older. gfortran 10 and newer needs `-fallow-argument-mismatch`, which the current mk already contains.

### 2.1. Conda toolchain

When the system package manager is unavailable, Miniforge + conda-forge can provide the same MPI/NetCDF stack. On the verification host, `apt-get` reached Debian mirrors through proxy `198.18.0.1` and returned HTTP 500 / SSL EOF, so system packages mostly could not be installed; the only package installed by hand was the `make` 4.4.1-2 `.deb`. The toolchain actually used is the conda environment named `coawst`, with Miniforge prefix `/workspace/miniforge3`.

```bash
mamba create -y -n coawst -c conda-forge \
  gfortran gcc gxx openmpi \
  "libnetcdf=*=mpi_openmpi*" \
  "netcdf-fortran=*=mpi_openmpi*" \
  "hdf5=*=mpi_openmpi*" \
  cmake make perl zlib libcurl compilers pkg-config tcsh
```

After `conda activate coawst`, PATH should include `gfortran`, `gcc`, `g++`, `mpicc`, `mpif90`, `nf-config`, `nc-config`, `cmake`, `make`, and `perl`.

### 2.3. Building MCT

The manual requires the bundled `Lib/MCT`: it is slightly modified relative to upstream and tested with COAWST. Configure MCT with the same `mpicc` / `mpif90` that will later build `coawstM`, and install into the in-tree `Lib/MCT` prefix so `MCT_INCDIR` / `MCT_LIBDIR` find the `.mod` files and static libraries.

```bash
source /workspace/coawst-env.sh
cd /workspace/COAWST/Lib/MCT
chmod +x configure config.guess config.sub install-sh mkinstalldirs
bash ./configure --prefix=/workspace/COAWST/Lib/MCT CC=mpicc FC=mpif90 F90=mpif90
make -j4
make install
```

After a clone, `configure` may lack the executable bit; use `bash ./configure` or `chmod +x` first. Fortran/MPI type-mismatch warnings under `-fallow-argument-mismatch` can be ignored.

| Artifact | Path |
|----------|------|
| `libmct.a` | `/workspace/COAWST/Lib/MCT/lib/libmct.a` (925K) |
| `libmpeu.a` | `/workspace/COAWST/Lib/MCT/lib/libmpeu.a` |
| modules | `/workspace/COAWST/Lib/MCT/include/*.mod` |

Logs: `/workspace/mct-configure.log`, `/workspace/mct-make.log`, `/workspace/mct-install.log`.

SCRIP weights are needed only for different grids or nesting. v3.9 can generate weight files at run time. The same-grid Inlet Coupled case has no pre-shipped `scrip_weights_inlet_test.nc` and still runs.

> **Warning**
>
> Build MCT with the same `mpif90` as COAWST and export `MCT_INCDIR` / `MCT_LIBDIR`. Without those exports the defaults often fall through to `/usr/local/mct/{include,lib}`, which the verification host does not have.

## 3. Environment variables

Build and run share a consistent path set: `NETCDF` points at the NetCDF prefix, `MCT_INCDIR` / `MCT_LIBDIR` at the MCT just built, and OpenMPI MCA parameters keep the transport layer from choosing the wrong backend on a restricted network. Cases that include WRF also need the run-time endianness variable `GFORTRAN_CONVERT_UNIT=big_endian`; keep that variable in the JOE_TC-only helper, not in the default environment script (see [5.2](#52-joe_tc-coupled)).

Load the default script before each build or run:

```bash
source /workspace/coawst-env.sh
```

The script is equivalent to:

```bash
source /workspace/miniforge3/etc/profile.d/conda.sh
conda activate coawst
export NETCDF=$(nf-config --prefix)
# -> /workspace/miniforge3/envs/coawst
export MCT_INCDIR=/workspace/COAWST/Lib/MCT/include
export MCT_LIBDIR=/workspace/COAWST/Lib/MCT/lib
export OMPI_MCA_btl=tcp,self
export OMPI_MCA_pml=ob1
```

Small test runs may also enable oversubscription:

```bash
export OMPI_MCA_rmaps_base_oversubscribe=true
```

For **JOE_TC** (with WRF), load the helper instead. It sources `coawst-env.sh`, then sets `OMPI_MCA_rmaps_base_oversubscribe=true` and the JOE_TC-only `GFORTRAN_CONVERT_UNIT=big_endian`:

```bash
source /workspace/coawst-env-joe_tc.sh
```

> **Warning**
>
> Do not put `GFORTRAN_CONVERT_UNIT=big_endian` into the default `coawst-env.sh`. Non-WRF cases would change endianness as a side effect.

- `NETCDF`: required by the WRF segment and overall I/O; with `USE_NETCDF4=on`, the ROMS side also resolves paths via `nf-config` / `nc-config`.
- `MCT_INCDIR` / `MCT_LIBDIR`: point at the built MCT.
- `Linux-gfortran.mk` uses `nf-config`/`nc-config` when `USE_NETCDF4=on`, and MCT via the two variables above.

You can also set `USE_MY_LIBS=yes` and edit `Compilers/my_build_paths.sh`. The INLET_TEST verification used `USE_MY_LIBS=no`.

## 4. Building applications

`build_coawst.sh` reads `COAWST_APPLICATION` and the header paths, decides which of ROMS / SWAN / WRF / WW3 to enable, and drives the compile. Switching applications means changing the application name and header directories in the script, and usually cleaning or rebuilding artifacts. A coupled build produces `coawstM` at the repository root (`coawstM.exe` on Windows); it does not produce standalone `wrf.exe` / `ocean.exe` / `swan.exe`.

### 4.1. Configuring `build_coawst.sh`

The script lives at the source root. Back it up before editing:

```bash
cd /workspace/COAWST
cp build_coawst.sh build_coawst.sh.orig
```

The shipped distribution sets `MY_ROOT_DIR` to a Cygwin path and defaults `which_MPI` to `intel`. A Linux + OpenMPI stack needs the real tree path and `openmpi`:

```diff
--- build_coawst.sh.orig
+++ build_coawst.sh
@@ MY_ROOT_DIR
-export   MY_ROOT_DIR=/cygdrive/d/models/COAWST
+export   MY_ROOT_DIR=/workspace/COAWST

@@ which_MPI
- export         which_MPI=intel         # compile with mpiifort library
+ #export         which_MPI=intel         # compile with mpiifort library
-#export         which_MPI=openmpi       # compile with OpenMPI library
+export         which_MPI=openmpi       # compile with OpenMPI library
```

Leave the remaining INLET_TEST defaults as shipped:

| Variable | Value |
|----------|-------|
| `COAWST_APPLICATION` | `INLET_TEST` (must be ALL CAPS; matches header `inlet_test.h`) |
| `FORT` | `gfortran` |
| `USE_MPI` / `USE_MPIF90` | `on` |
| `USE_NETCDF4` | `on` |
| `USE_MY_LIBS` | `no` |
| `MY_HEADER_DIR` / `MY_ANALYTICAL_DIR` | `${MY_PROJECT_DIR}/Projects/Inlet_test/Coupled` |
| `BINDIR` | `./` |
| `SCRATCH_DIR` | `./Build_roms` |

`inlet_test.h` defines `ROMS_MODEL`, `SWAN_MODEL`, and `MCT_LIB`, with no WRF/WW3, so `make wrf` / `ww3` / `wrfhydro` are no-ops.

> **Note**
>
> `COAWST_APPLICATION` must be the application name in ALL CAPS; the header file itself may be lowercase (e.g. `inlet_test.h`). Do not mix older docs’ `coawst.bash` / `build_coawst.bash` with v3.9’s `build_coawst.sh`.

To switch to JOE_TC, change the application name, `NETCDF`, and header directories on top of the Inlet settings:

```diff
-export   COAWST_APPLICATION=INLET_TEST
+export   COAWST_APPLICATION=JOE_TC
-#export  NETCDF=${NETCDF_INCDIR}/../
+export  NETCDF=$(nf-config --prefix)
-   export     MY_HEADER_DIR=${MY_PROJECT_DIR}/Projects/Inlet_test/Coupled
-   export MY_ANALYTICAL_DIR=${MY_PROJECT_DIR}/Projects/Inlet_test/Coupled
+   export     MY_HEADER_DIR=${MY_PROJECT_DIR}/Projects/JOE_TC/Coupled
+   export MY_ANALYTICAL_DIR=${MY_PROJECT_DIR}/Projects/JOE_TC/Coupled
```

Keep `FORT=gfortran`, `which_MPI=openmpi`, and `USE_NETCDF4=on`.

### 4.2. INLET_TEST (ROMS+SWAN)

INLET_TEST Coupled exercises ROMS–SWAN MCT coupling on an idealized inlet. It is the non-WRF baseline: the header enables only ocean and waves, the build is short, and it is a good first check that the toolchain and `coawstM` link correctly.

```bash
source /workspace/coawst-env.sh
cd /workspace/COAWST
./build_coawst.sh -j 4
```

The script order is `make mct_params` → `make wrf` → `make wrfhydro` → `make ww3` → `make swan` → the main `make` (ROMS/driver). Flags such as `-nocleanwrf` skip cleaning. On the verification host the wall clock was about **58 s** (including SWAN cmake and the ROMS/SWAN link), with no `mpif.h` race and no need for a serial retry. The link line is `mpif90 … -o coawstM -lROMS libswan41.51.a -lnetcdff -lnetcdf … -lmct -lmpeu`. Success means `coawstM` appears at the repository root; an occasional “undefined wrf.main” warning under a non-WRF configuration is acceptable.

| Item | Value |
|------|-------|
| Executable | `/workspace/COAWST/coawstM` |
| Size | 9.9M (10371976 bytes) |
| Build directory | `/workspace/COAWST/Build_roms/` |
| SWAN library | `/workspace/COAWST/SWAN/build/lib/libswan41.51.a` |
| Full log | `/workspace/coawst-build.log` |

> **Warning**
>
> If a parallel make reports a missing `mpif.h`, drop `-j` or use `-j 1` and rebuild.

### 4.3. JOE_TC Coupled (WRF+ROMS+SWAN)

The header `Projects/JOE_TC/Coupled/joe_tc.h` preselects **ExpG** (`WRF_MODEL` + `ROMS_MODEL` + `SWAN_MODEL`, plus `MCT_LIB` and related options). This configuration builds a full WRF and takes much longer than INLET_TEST’s ~58 s. Back up the Inlet binary and script before switching:

```bash
cd /workspace/COAWST
cp -a coawstM coawstM.inlet_test
cp -a build_coawst.sh build_coawst.sh.inlet_test
```

Inside `build_coawst.sh`, `make wrfclean` runs `WRF/clean -a; ./configure` interactively. Answers can be piped: option **34** is GNU (gfortran/gcc) dmpar; nesting option **1** is basic.

```bash
source /workspace/coawst-env.sh
cd /workspace/COAWST
printf '34\n1\n' | ./build_coawst.sh -j 4
```

The resulting `configure.wrf` already has `DM_FC=mpif90`, `DM_CC=mpicc`, and gfortran ≥10’s `FCCOMPAT=-fallow-argument-mismatch -fallow-invalid-boz`. **Do not patch `configure.wrf` further.** Moving nest is unavailable without `rpc/types.h`; this case has `max_dom=1`, so that warning is harmless.

If `/bin/csh` is missing on the first attempt, configure can succeed but `./compile` fails after about 61 s with exit 2, and the ROMS side reports a missing `module_wrf_top.mod` (log `/workspace/joe_tc-build.log`). After providing `/bin/csh`, keep the written `configure.wrf` and the JOE_TC `mct_params` already in `Build_roms`, and rebuild without cleaning:

```bash
./build_coawst.sh -j 4 -noclean -nocleanwrf -nocleanswan
```

On the verification host the wall clock was about **27 m 31 s** (real), exit 0, log `/workspace/joe_tc-build2.log`. `checkout_externals: Permission denied` comes from physics submodules that are already vendored; the missing `main` when linking `wrf.exe` is expected because COAWST links WRF into `coawstM` and does not produce a standalone `wrf.exe`—both can be ignored. `real.exe` / `ndown.exe` / `tc.exe` were built.

| Item | Value |
|------|-------|
| Executable | `/workspace/COAWST/coawstM` |
| Size | 65 MB (68047632 bytes) |
| Backup name | `coawstM.joe_tc` |
| `nm … \| grep -ci module_wrf_top` | 34 |

> **Warning**
>
> A full clean deletes `Build_roms`. Combined with `-nocleanwrf`, the script also skips `mct_params`; watch this when switching applications.

### 4.4. Tips on practical use

- **Parallelism**: `./build_coawst.sh -j 4` works for both INLET_TEST and JOE_TC. Switch to `-j 1` if an `mpif.h` race appears.
- **Skip cleaning**: after a partial failure, `-noclean -nocleanwrf -nocleanswan` keeps `configure.wrf` and existing artifacts. Do not rely on those flags to skip `mct_params` when changing applications.
- **WRF configure**: GNU dmpar with basic nesting is `printf '34\n1\n'`.
- **gfortran 15**: `-fallow-argument-mismatch` is already in `Linux-gfortran.mk` and the MCT configure. MPI type-mismatch warnings can be ignored.
- **mk options**: do not leave Intel-only flags (such as `-assume byterecl`) in the gfortran mk; on older trees that breaks SWAN/gfortran.
- **WRF**: let `build_coawst.sh` compile WRF when the application enables it; do not build WRF standalone for coupled apps.
- **Switching cases**: after changing headers or paths, clean or rebuild `Build_roms` and WRF artifacts.
- **Success check**: `coawstM` appears at the repository root. INLET_TEST is about 9.9M; JOE_TC is about 65 MB.

## 5. Running applications

The root `coawstM` reads `coupling_*.in` and assigns MPI ranks to each model from `NnodesATM` / `NnodesWAV` / `NnodesOCN`. `mpirun -np` must equal the sum of those `Nnodes*` values. When WRF and ROMS both run, `nproc_x * nproc_y` in `namelist.input` must also equal `NnodesATM`, and `NtileI * NtileJ` in the ROMS `.in` must equal `NnodesOCN` (see [5.3](#53-processor-layout)).

### 5.1. INLET_TEST Coupled

In `Projects/Inlet_test/Coupled/coupling_inlet_test.in`, `NnodesWAV=1` and `NnodesOCN=1`, so use **`mpirun -np 2`**. A short run can be truncated with `timeout`; drop the timeout for a full integration once coupling exchanges and output files look healthy. The full case is `NTIMES=720`, `DT=60 s` (about 12 h of model time). The southern boundary is closed, the northern boundary is a sinusoidal water level, and SWAN injects roughly 1 m wave height from north to south; grids and inputs already live under `Projects/Inlet_test/Coupled`.

```bash
source /workspace/coawst-env.sh
cd /workspace/COAWST
timeout 240s mpirun -np 2 ./coawstM Projects/Inlet_test/Coupled/coupling_inlet_test.in \
  > /workspace/inlet_test_run.out 2>&1
```

On the verification host startup succeeded and ROMS and SWAN began exchanging fields. After 240 s the processes exited because of `timeout` (exit 124) with no run-time error; the short run reached about timestep **254** (about 4.2 h of model time). stdout recorded the rank split (Ocean rank 0, Waves rank 1), `ROMS version 4.3` (`mpif90` / gfortran, `MCT_LIB`, `SWAN_COUPLING`), repeated `SWAN grid 1 sent wave data to ROMS` / `ROMS … sent data to SWAN` lines with finite HSIGN / DEPTH / VEL, and outputs `ocean_his_coupled.nc`, `ocean_avg_coupled.nc`, `ocean_sta.nc`, and `PRINT01`.

Full integration without `timeout`:

```bash
source /workspace/coawst-env.sh
cd /workspace/COAWST
mpirun -np 2 ./coawstM Projects/Inlet_test/Coupled/coupling_inlet_test.in
```

There is no `Projects/Inlet_test/Coupled/scrip_weights_inlet_test.nc` in the tree. Same-grid Coupled uses the MCT same-grid path and needs no pre-generated weights. For multi-grid or different-grid cases, v3.9 can generate SCRIP weights at run time; the file name is set by `SCRIP_COAWST_NAME`, and an existing file is reused.

On PBS hosts, follow the repository’s `run_coawst` or the manual’s `run_nemo` and wrap `mpirun` plus `coupling_*.in` in a job script. On SLURM use `sbatch` / `squeue`.

### 5.2. JOE_TC Coupled

In `coupling_joe_tc.in`, `NnodesATM=1`, `NnodesWAV=1`, and `NnodesOCN=1`, so use **`mpirun -np 3`**. WRF inputs live under `Projects/JOE_TC/` (not under `Coupled/`): `namelist.input`, `wrfinput_d01`, `wrfbdy_d01` (`run_hours=120`, `time_step=25`, `nproc_x=nproc_y=1`). ROMS uses `NtileI=NtileJ=1`, `NTIMES=17280`, `DT=25 s`. The verification window was 2026-10-28 (America/Los_Angeles, about 07:22–08:03).

#### 5.2.1. Run-directory setup (repository root)

WRF looks in the run directory for the namelist, boundary/initial fields, and radiation/physics tables. The manual requires copying namelist / wrfinput / wrfbdy to `root_dir` and linking the tables from `WRF/run` into the root:

```bash
cd /workspace/COAWST
cp Projects/JOE_TC/{namelist.input,wrfinput_d01,wrfbdy_d01} .
for f in WRF/run/*; do
  b=$(basename "$f")
  case $b in namelist*|*.exe|README*|CMake*|Makefile) ;; *)
    [ -e "$b" ] || ln -s "$f" "$b"
  ;; esac
done
```

#### 5.2.2. big_endian is required

Without the endianness setting, the WRF rank fails immediately with `At line 6925 of file module_ra_rrtm.f90 (unit = 10, file = 'RRTM_DATA') Fortran runtime error: End of file`.

WRF objects are compiled with `-fconvert=big-endian`. gfortran applies that conversion only when it compiles the main program; here the main program is ROMS’s `master.f90`, built without the flag, so big-endian WRF tables are read as little-endian and hit EOF. Export before running:

```bash
export GFORTRAN_CONVERT_UNIT=big_endian
```

A permanent fix is to add `-fconvert=big-endian -frecord-marker=4` to `FFLAGS` under the `USE_WRF` branch in `Compilers/Linux-gfortran.mk` and rebuild. The verification host did not change the mk. Loading the helper is enough:

```bash
source /workspace/coawst-env-joe_tc.sh
```

#### 5.2.3. Short run

A short run can be truncated with a 600 s `timeout` and a `SIGKILL` 30 s later:

```bash
source /workspace/coawst-env-joe_tc.sh
cd /workspace/COAWST
timeout --kill-after=30s 600s mpirun -np 3 ./coawstM Projects/JOE_TC/Coupled/coupling_joe_tc.in \
  > /workspace/joe_tc_run.out 2>&1
```

On the verification host startup succeeded: Ocean / Waves / Atmos on ranks 0 / 1 / 2. After 600 s the processes exited because of `timeout` (exit 124) with no run-time error. WRF had reached about **2005-09-01_03:05:25** (about 3 h of the 120 h run), roughly 1.25 s of wall clock per 25 s model step. There were **19** three-way coupling cycles covering all 12 exchange message types (for example `WRF … sent data to ROMS`, `SWAN … sent data to WRF`, and `ROMS … sent data to SWAN`). Outputs included `wrfout_d01_2005-09-01_00:00:00` (about 100 MB), `ocean_avg.nc`, `ocean_dia.nc`, and `ocean_rst.nc`; `ocean_joe_tcs_his.nc` also appeared with an anomalous mtime and was not inspected.

At that rate a full **120 h** on 3 ranks would take roughly **2 days**. Increasing `NnodesATM` while matching `nproc_x * nproc_y`, and increasing `NtileI * NtileJ`, shortens the wall clock. Full integration without `timeout`:

```bash
source /workspace/coawst-env-joe_tc.sh
cd /workspace/COAWST
mpirun -np 3 ./coawstM Projects/JOE_TC/Coupled/coupling_joe_tc.in
```

You can also switch to ExpA1 (WRF+SWAN only) or ExpA (WRF+ROMS only). For WRF–ROMS coupling, prefer `sst_update = 1` and set `io_form_auxinput4`.

### 5.3. Processor layout

Coupled process counts are set by three layers that must stay aligned; otherwise the MPI partition disagrees with each model’s internal decomposition:

| Layer | Source | Meaning |
|-------|--------|---------|
| `NnodesATM` / `NnodesWAV` / `NnodesOCN` | `coupling_*.in` | MPI ranks for atmosphere / waves / ocean; their sum equals `mpirun -np` |
| `nproc_x` / `nproc_y` | WRF `namelist.input` | WRF domain decomposition; `nproc_x * nproc_y` should equal `NnodesATM` |
| `NtileI` / `NtileJ` | ROMS ocean `.in` | ROMS tile decomposition; `NtileI * NtileJ` should equal `NnodesOCN` |

The two short runs used `mpirun -np` 2 and 3:

| Case | `mpirun -np` | Nnodes* | WRF | ROMS |
|------|--------------|---------|-----|------|
| INLET_TEST Coupled | 2 | WAV=1, OCN=1 | (none) | (set by NnodesOCN) |
| JOE_TC Coupled | 3 | ATM=1, WAV=1, OCN=1 | `nproc_x=nproc_y=1` | `NtileI=NtileJ=1` |

> **Note**
>
> When increasing parallelism, edit `coupling_*.in`, the WRF namelist, and the ROMS `.in` together, then set `mpirun -np` to the new sum of `Nnodes*`.

## 6. Common pitfalls and recommended practices

The failures below were confirmed on the verification host during deploy and short runs. Numbering is not priority order.

1. **apt unavailable** (proxy `198.18.0.1` → 500/SSL). Fix: conda-forge env `coawst`, plus the curl-installed `make` `.deb`.
2. **MCT `./configure` not executable**. Fix: `bash ./configure` or `chmod +x`.
3. **MCT must use the same `mpif90` as COAWST**, with `MCT_INCDIR` / `MCT_LIBDIR` exported. Otherwise “module file was not generated by this compiler” or a missing `m_MCTWorld` is common.
4. **`COAWST_APPLICATION` must be ALL CAPS** (`INLET_TEST`), matching `inlet_test.h`; lowercase matching fails.
5. **Shipped `MY_ROOT_DIR` is the Cygwin path** `/cygdrive/d/models/COAWST`; on Linux set the real path (`/workspace/COAWST` on the verification host).
6. **Shipped `which_MPI=intel`**; this stack uses `openmpi`.
7. **gfortran 15**: `-fallow-argument-mismatch` is already in `Linux-gfortran.mk` and the MCT configure; MPI type-mismatch warnings can be ignored.
8. **`mpirun -np` equals the sum of `Nnodes*`** (2 for Inlet Coupled; 3 for JOE_TC Coupled).
9. **`./build_coawst.sh -j 4` works**; on an `mpif.h` race, rebuild without parallelism or with `-j 1`.
10. **Do not compile WRF standalone for coupled apps**; let `build_coawst.sh` own WRF when it is enabled.
11. **Rebuild when switching cases**: after changing headers / paths, clean or rebuild `Build_roms` and WRF artifacts.
12. **Do not leave Intel-only flags in the gfortran mk** (e.g. `-assume byterecl`); on older trees that breaks SWAN/gfortran.
13. **WRF configure needs m4 / flex / bison** (conda-forge); `./compile` needs `/bin/csh` (e.g. `ln -sf …/tcsh /bin/csh`).
14. **Interactive WRF configure**: `printf '34\n1\n' | ./build_coawst.sh -j 4` (GNU dmpar + basic nesting).
15. **JOE_TC runs require `GFORTRAN_CONVERT_UNIT=big_endian`**, or `RRTM_DATA` hits EOF; use `/workspace/coawst-env-joe_tc.sh`, not the default `coawst-env.sh`.
16. **JOE_TC namelist / wrfinput / wrfbdy live under `Projects/JOE_TC/`**, not `Coupled/`; copy them to the root and symlink `WRF/run` tables before running.
17. **Partial-rebuild flags**: `-noclean -nocleanwrf -nocleanswan` keep `configure.wrf`; a full clean deletes `Build_roms`, and with `-nocleanwrf` the script skips `mct_params`.

Recommended practice: validate the ROMS+SWAN+MCT toolchain with INLET_TEST before building JOE_TC; keep the default env and the WRF-aware env separate (`coawst-env.sh` vs `coawst-env-joe_tc.sh`); back up `coawstM` and `build_coawst.sh` before switching applications (the verification host kept `coawstM.inlet_test` / `coawstM.joe_tc`); truncate short runs with `timeout`, then drop the timeout for a full integration once exchanges and outputs look healthy.

## 7. Further applications

The repository also ships the cases below. Paths and model combinations come from the tree layout and manual excerpts; **they were not compiled or run on the verification host**.

| Case | Path | Models |
|------|------|--------|
| JOE_TC DiffGrid | `Projects/JOE_TC/DiffGrid` | ROMS+SWAN and WRF on different grids |
| Sandy | `Projects/Sandy/` | Full storm; `coupling_sandy.in`; often a PBS `run_coawst` example |

In DiffGrid, ROMS/SWAN share one grid and WRF uses another. v3.9 can auto-generate weights such as `scrip_joe_tc_diffgrid.nc`, or you can build `Lib/SCRIP_COAWST` and run `scrip_coawst`. The header must enable `MCT_INTERP_WV2AT` and `MCT_INTERP_OC2AT`; DiffGrid case H already sets both.

Sandy is a full storm case and often appears as a PBS `run_coawst` example. Take node counts and inputs from that directory’s `coupling_sandy.in` and `sandy.h`. Set `mpirun -np` to `NnodesATM + NnodesWAV + NnodesOCN`. When switching applications, rebuild from a clean state and update `COAWST_APPLICATION` and `MY_*_DIR` as above.
