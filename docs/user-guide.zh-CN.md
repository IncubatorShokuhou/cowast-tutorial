# COAWST 编译与运行指南

[English](user-guide.en.md) · [首页](../README.md) · [中文首页](../README.zh-CN.md)

**COAWST**（Coupled-Ocean-Atmosphere-Wave-Sediment Transport Modeling System）通过 MCT 把 ROMS、SWAN/WW3，以及可选的 WRF，耦合进同一套可执行文件。编译要求同一套 Fortran / MPI / NetCDF 工具链，并与 MCT 对齐；运行时 `mpirun -np` 必须等于 `coupling_*.in` 里各 `Nnodes*` 之和。本指南说明在 Linux 上用 COAWST v3.9 编译并短时试跑 **INLET_TEST**（ROMS+SWAN）与 **JOE_TC Coupled**（WRF+ROMS+SWAN）。独立 WRF 的编译与运行步骤不在此重复。

> **Note**
>
> 口语里的 cowast / COWAST 指同一套 USGS 系统；官方拼写为 **COAWST**。许可证为 USGS 公有领域 / CC0 1.0，标准 ROMS–SWAN–WRF–WW3 路径不依赖专有库。

## 1. Getting started

源码来自 `https://github.com/DOI-USGS/COAWST.git` 的 **COAWST v3.9**，提交 `81df2ed`（完整哈希 `81df2edcd175fb87426b4d913f4fdaa42cfc50ad`）。耦合算例由根目录的 `build_coawst.sh` 统一驱动：脚本按应用头文件决定启用哪些模型，再依次编译 MCT 参数，然后是可选的 WRF/WW3 与 SWAN，最后是 ROMS 主程序。不要对耦合应用单独执行 `./compile em_real`。仓库还包含用户手册 `COAWST_User_Manual.docx`，以及 ROMS、WRF、WPS、SWAN、WW3、InWave、Master、Lib、Compilers、Projects 等目录。**Sandy** 与 **JOE_TC DiffGrid** 未在本文验证主机上编译。

```bash
cd /workspace
git clone --depth 1 https://github.com/DOI-USGS/COAWST.git
# 结果：/workspace/COAWST（约 1.8G），commit 81df2ed
```

GitHub 克隆可用；备选地址是 `https://code.usgs.gov/coawstmodel/COAWST`。

> **Note**
>
> | 项 | 值 |
> |----|-----|
> | 主机 | Debian 13（trixie），x86_64，8 CPU |
> | 工作区 | `/workspace`，约 110G 可用 |
> | 验证日期 | 2026-10-28（America/Los_Angeles） |
> | 已验证算例 | INLET_TEST Coupled；JOE_TC Coupled |
> | 未验证 | Sandy；JOE_TC DiffGrid |

## 2. Prerequisites

COAWST 把多个 Fortran 模型链进同一个 `coawstM`。NetCDF、MPI 与 MCT 必须由同一套 `mpicc` / `mpif90` 编译；混用不同编译器会产生 “module file was not generated by this compiler” 或找不到 `m_MCTWorld` 一类错误。所需组件包括 gfortran、C/C++、OpenMPI、NetCDF-C 与 NetCDF-Fortran（NetCDF4）、HDF5、cmake、make、perl、git，以及仓库自带的 **MCT**（`Lib/MCT`，须先编）。含 WRF 的应用还需要 m4、flex、bison 和 `/bin/csh`。

gfortran 建议 ≥ 7：仓库的 `Linux-gfortran.mk` 在 gfortran ≤6 时报错。gfortran ≥10 需要 `-fallow-argument-mismatch`，当前 mk 已包含该选项。

### 2.1. Conda 工具链

系统包管理器不可用，可用 Miniforge + conda-forge 搭同一套 MPI/NetCDF 工具链。验证主机上 `apt-get` 经代理 `198.18.0.1` 访问 Debian 镜像返回 HTTP 500 / SSL EOF，系统包基本装不上；唯一手工装上的是 `make` 4.4.1-2 的 `.deb`。实际使用的是环境名 `coawst` 的 conda 环境，Miniforge 前缀 `/workspace/miniforge3`。

```bash
mamba create -y -n coawst -c conda-forge \
  gfortran gcc gxx openmpi \
  "libnetcdf=*=mpi_openmpi*" \
  "netcdf-fortran=*=mpi_openmpi*" \
  "hdf5=*=mpi_openmpi*" \
  cmake make perl zlib libcurl compilers pkg-config tcsh
```

`conda activate coawst` 之后，PATH 上应有 `gfortran`、`gcc`、`g++`、`mpicc`、`mpif90`、`nf-config`、`nc-config`、`cmake`、`make`、`perl`。

| 组件 | 版本 |
|------|------|
| gfortran / gcc / g++ | 15.3.0（conda-forge） |
| OpenMPI | 5.0.11（`mpicc` / `mpif90`） |
| libnetcdf | 4.10.0 mpi_openmpi |
| netcdf-fortran | 4.6.4 mpi_openmpi |
| HDF5 | 2.2.0 mpi_openmpi |
| cmake | 4.4.5 |
| make | 4.4.1 |
| perl | 5.44 |
| tcsh | 6.24.16 |

含 WRF 的应用再装 m4、flex、bison，并把 conda 里的 tcsh 链到 `/bin/csh`（WRF 的 `./compile` shebang 为 `#!/bin/csh`）：

```bash
mamba install -n coawst -c conda-forge m4 flex bison
sudo ln -sf /workspace/miniforge3/envs/coawst/bin/tcsh /bin/csh
```

> **Warning**
>
> 缺 `m4` 时 WRF configure 报 `'m4' utility not found`。缺 `/bin/csh` 时 `./compile` 报 `not found`。编译时可另设 `NETCDF_classic=0`、`WRFIO_NCD_LARGE_FILE_SUPPORT=1`。

### 2.3. 编译 MCT

手册要求使用仓库自带的 `Lib/MCT`：它相对上游略有修改，并已按 COAWST 测过。MCT 必须用与随后编译 `coawstM` 相同的 `mpicc` / `mpif90` 配置，安装前缀指向树内 `Lib/MCT`，以便 `MCT_INCDIR` / `MCT_LIBDIR` 能找到 `.mod` 与静态库。

```bash
source /workspace/coawst-env.sh
cd /workspace/COAWST/Lib/MCT
chmod +x configure config.guess config.sub install-sh mkinstalldirs
bash ./configure --prefix=/workspace/COAWST/Lib/MCT CC=mpicc FC=mpif90 F90=mpif90
make -j4
make install
```

clone 之后 `configure` 可能没有可执行位；用 `bash ./configure`，或先 `chmod +x`。在 `-fallow-argument-mismatch` 下出现的 Fortran/MPI 类型不匹配警告可以忽略。

| 产物 | 路径 |
|------|------|
| `libmct.a` | `/workspace/COAWST/Lib/MCT/lib/libmct.a`（925K） |
| `libmpeu.a` | `/workspace/COAWST/Lib/MCT/lib/libmpeu.a` |
| modules | `/workspace/COAWST/Lib/MCT/include/*.mod` |

日志在 `/workspace/mct-configure.log`、`/workspace/mct-make.log`、`/workspace/mct-install.log`。

SCRIP 权重只在不同网格或嵌套时需要。v3.9 可以在运行期生成权重文件。同网格 Inlet Coupled 没有预置 `scrip_weights_inlet_test.nc`，仍可跑通。

> **Warning**
>
> MCT 必须用与 COAWST 相同的 `mpif90`，并导出 `MCT_INCDIR` / `MCT_LIBDIR`。不设时默认常落到 `/usr/local/mct/{include,lib}`，验证主机没有那套路径。

## 3. Environment variables

编译与运行都依赖一组一致的路径：`NETCDF` 指向 NetCDF 前缀，`MCT_INCDIR` / `MCT_LIBDIR` 指向上一节编好的 MCT，OpenMPI MCA 参数避免在受限网络环境里选错传输层。含 WRF 的算例还需要运行期字节序变量 `GFORTRAN_CONVERT_UNIT=big_endian`；该变量只应出现在 JOE_TC 专用 helper 中，不要写进默认环境脚本（见 [5.2](#52-joe_tc-coupled)）。

每次编译或运行前加载默认脚本：

```bash
source /workspace/coawst-env.sh
```

该脚本等价于：

```bash
source /workspace/miniforge3/etc/profile.d/conda.sh
conda activate coawst
export NETCDF=$(nf-config --prefix)
# -> /workspace/miniforge3/envs/coawst
export MCT_INCDIR=/workspace/COAWST/Lib/MCT/include
export MCT_LIBDIR=/workspace/COAWST/Lib/MCT/lib
export OMPI_MCA_btl=tcp,self
export OMPI_MCA_pml=ob1
```

小规模试跑可按需打开超订：

```bash
export OMPI_MCA_rmaps_base_oversubscribe=true
```

**JOE_TC**（含 WRF）改加载 helper。它先 `source` 上面的 `coawst-env.sh`，再设置 `OMPI_MCA_rmaps_base_oversubscribe=true`，以及仅 JOE_TC 需要的 `GFORTRAN_CONVERT_UNIT=big_endian`：

```bash
source /workspace/coawst-env-joe_tc.sh
```

> **Warning**
>
> 不要把 `GFORTRAN_CONVERT_UNIT=big_endian` 写进默认的 `coawst-env.sh`。无 WRF 算例的字节序会因此改变。

- `NETCDF`：WRF 段与整体 I/O 需要；`USE_NETCDF4=on` 时 ROMS 侧还会通过 `nf-config` / `nc-config` 取路径。
- `MCT_INCDIR` / `MCT_LIBDIR`：指向已编译的 MCT。
- `Linux-gfortran.mk` 在 `USE_NETCDF4=on` 时走 `nf-config`/`nc-config`，MCT 走上述两个变量。

也可以设 `USE_MY_LIBS=yes` 并修改 `Compilers/my_build_paths.sh`。INLET_TEST 验证使用的是 `USE_MY_LIBS=no`。

## 4. Building applications

`build_coawst.sh` 读取 `COAWST_APPLICATION` 与头文件路径，决定启用 ROMS / SWAN / WRF / WW3，并统一驱动编译。切换应用时要改脚本里的应用名和头文件目录，通常还要清理或重建构建产物；耦合构建产出根目录的 `coawstM`（Windows 上为 `coawstM.exe`），不另产独立的 `wrf.exe` / `ocean.exe` / `swan.exe`。

### 4.1. Configuring `build_coawst.sh`

脚本在源码根目录。修改前先备份：

```bash
cd /workspace/COAWST
cp build_coawst.sh build_coawst.sh.orig
```

发行版把 `MY_ROOT_DIR` 设成 Cygwin 路径，并把 `which_MPI` 默认成 `intel`。Linux + OpenMPI 栈需要改成实际树路径与 `openmpi`：

```diff
--- build_coawst.sh.orig
+++ build_coawst.sh
@@ MY_ROOT_DIR
-export   MY_ROOT_DIR=/cygdrive/d/models/COAWST
+export   MY_ROOT_DIR=/workspace/COAWST

@@ which_MPI
- export         which_MPI=intel         # compile with mpiifort library
+ #export         which_MPI=intel         # compile with mpiifort library
-#export         which_MPI=openmpi       # compile with OpenMPI library
+export         which_MPI=openmpi       # compile with OpenMPI library
```

INLET_TEST 保持发行默认的其余变量：

| 变量 | 值 |
|------|-----|
| `COAWST_APPLICATION` | `INLET_TEST`（必须全大写，对应头文件 `inlet_test.h`） |
| `FORT` | `gfortran` |
| `USE_MPI` / `USE_MPIF90` | `on` |
| `USE_NETCDF4` | `on` |
| `USE_MY_LIBS` | `no` |
| `MY_HEADER_DIR` / `MY_ANALYTICAL_DIR` | `${MY_PROJECT_DIR}/Projects/Inlet_test/Coupled` |
| `BINDIR` | `./` |
| `SCRATCH_DIR` | `./Build_roms` |

`inlet_test.h` 定义了 `ROMS_MODEL`、`SWAN_MODEL`、`MCT_LIB`，没有 WRF/WW3，因此 `make wrf` / `ww3` / `wrfhydro` 为空操作。

> **Note**
>
> `COAWST_APPLICATION` 必须是全大写应用名；头文件本身可以小写（如 `inlet_test.h`）。旧文档里的 `coawst.bash` / `build_coawst.bash` 不要和 v3.9 的 `build_coawst.sh` 混用。

切到 JOE_TC 时，在 Inlet 配置上改应用名、`NETCDF` 和头文件目录：

```diff
-export   COAWST_APPLICATION=INLET_TEST
+export   COAWST_APPLICATION=JOE_TC
-#export  NETCDF=${NETCDF_INCDIR}/../
+export  NETCDF=$(nf-config --prefix)
-   export     MY_HEADER_DIR=${MY_PROJECT_DIR}/Projects/Inlet_test/Coupled
-   export MY_ANALYTICAL_DIR=${MY_PROJECT_DIR}/Projects/Inlet_test/Coupled
+   export     MY_HEADER_DIR=${MY_PROJECT_DIR}/Projects/JOE_TC/Coupled
+   export MY_ANALYTICAL_DIR=${MY_PROJECT_DIR}/Projects/JOE_TC/Coupled
```

`FORT=gfortran`、`which_MPI=openmpi`、`USE_NETCDF4=on` 保持不变。

### 4.2. INLET_TEST（ROMS+SWAN）

INLET_TEST Coupled 在理想化入口上检验 ROMS–SWAN 的 MCT 耦合，是不含 WRF 的基线：头文件只打开海洋与波浪，构建时间短，适合先验证工具链与 `coawstM` 链接是否正确。

```bash
source /workspace/coawst-env.sh
cd /workspace/COAWST
./build_coawst.sh -j 4
```

脚本顺序为 `make mct_params` → `make wrf` → `make wrfhydro` → `make ww3` → `make swan` → 主 `make`（ROMS/驱动）。`-nocleanwrf` 等参数可以跳过清理。验证主机上墙钟约 **58 s**（含 SWAN cmake 与 ROMS/SWAN 链接），未出现 `mpif.h` 竞态，不需要改成串行重试。链接行为 `mpif90 … -o coawstM -lROMS libswan41.51.a -lnetcdff -lnetcdf … -lmct -lmpeu`。成功时根目录出现 `coawstM`；无 WRF 配置下偶发的 “undefined wrf.main” 警告可以接受。

| 项 | 值 |
|----|-----|
| 可执行文件 | `/workspace/COAWST/coawstM` |
| 大小 | 9.9M（10371976 bytes） |
| 构建目录 | `/workspace/COAWST/Build_roms/` |
| SWAN 库 | `/workspace/COAWST/SWAN/build/lib/libswan41.51.a` |
| 完整日志 | `/workspace/coawst-build.log` |

> **Warning**
>
> 并行 make 若报 `mpif.h` 找不到，去掉 `-j` 或改用 `-j 1` 再编一次。

### 4.3. JOE_TC Coupled（WRF+ROMS+SWAN）

头文件 `Projects/JOE_TC/Coupled/joe_tc.h` 预选 **ExpG**（`WRF_MODEL` + `ROMS_MODEL` + `SWAN_MODEL`，以及 `MCT_LIB` 等）。该配置会编译完整 WRF，墙钟远长于 INLET_TEST 的约 58 s。切换算例前备份 Inlet 的二进制和脚本：

```bash
cd /workspace/COAWST
cp -a coawstM coawstM.inlet_test
cp -a build_coawst.sh build_coawst.sh.inlet_test
```

`build_coawst.sh` 里的 `make wrfclean` 会交互执行 `WRF/clean -a; ./configure`。可用管道作答：选项 **34** 是 GNU（gfortran/gcc）dmpar，嵌套选项 **1** 是 basic。

```bash
source /workspace/coawst-env.sh
cd /workspace/COAWST
printf '34\n1\n' | ./build_coawst.sh -j 4
```

生成的 `configure.wrf` 已有 `DM_FC=mpif90`、`DM_CC=mpicc`，以及 gfortran ≥10 的 `FCCOMPAT=-fallow-argument-mismatch -fallow-invalid-boz`，**不必再改 `configure.wrf`**。缺少 `rpc/types.h` 时 moving nest 不可用；本算例 `max_dom=1`，该警告无影响。

首次尝试时若缺少 `/bin/csh`，configure 可通过，但 `./compile` 约 61 s 后以 exit 2 失败，ROMS 侧报缺 `module_wrf_top.mod`（日志 `/workspace/joe_tc-build.log`）。补上 `/bin/csh` 之后，保留已写好的 `configure.wrf` 和 `Build_roms` 里的 JOE_TC `mct_params`，跳过清理重编：

```bash
./build_coawst.sh -j 4 -noclean -nocleanwrf -nocleanswan
```

验证主机上墙钟约 **27 m 31 s**（real），exit 0，日志 `/workspace/joe_tc-build2.log`。`checkout_externals: Permission denied` 来自已经 vendored 的物理子模块；`wrf.exe` 链接时缺少 `main`，是因为 COAWST 把 WRF 链进 `coawstM`、不另产 `wrf.exe`——这两条都可以忽略。`real.exe` / `ndown.exe` / `tc.exe` 已经编出。

| 项 | 值 |
|----|-----|
| 可执行文件 | `/workspace/COAWST/coawstM` |
| 大小 | 65 MB（68047632 bytes） |
| 备份名 | `coawstM.joe_tc` |
| `nm … \| grep -ci module_wrf_top` | 34 |

> **Warning**
>
> 全量 clean 会删掉 `Build_roms`；若同时带 `-nocleanwrf`，脚本还会跳过 `mct_params`，换应用时注意。

### 4.4. Tips on practical use

- **并行度**：`./build_coawst.sh -j 4` 对 INLET_TEST 与 JOE_TC 均可用。出现 `mpif.h` 竞态时改 `-j 1`。
- **跳过清理**：部分失败后用 `-noclean -nocleanwrf -nocleanswan` 保留 `configure.wrf` 和已有产物。换应用时不要靠这些标志跳过 `mct_params`。
- **WRF configure**：GNU dmpar 加 basic nesting 对应 `printf '34\n1\n'`。
- **gfortran 15**：`-fallow-argument-mismatch` 已在 `Linux-gfortran.mk` 和 MCT configure 中。MPI 类型不匹配警告可以忽略。
- **mk 选项**：gfortran 的 mk 里不要留 Intel 专用选项（如 `-assume byterecl`）。旧树上这会使 SWAN/gfortran 失败。
- **WRF**：耦合应用在启用 WRF 时由 `build_coawst.sh` 编译，不要单独编 WRF。
- **切换算例**：改 header 或路径之后，清理或重建 `Build_roms` 和 WRF 产物。
- **成功标志**：根目录出现 `coawstM`。INLET_TEST 约 9.9M，JOE_TC 约 65 MB。

## 5. Running applications

根目录的 `coawstM` 读取 `coupling_*.in`，按其中的 `NnodesATM` / `NnodesWAV` / `NnodesOCN` 把 MPI 进程分给各模型。`mpirun -np` 必须等于各 `Nnodes*` 之和；若同时启用 WRF 与 ROMS，还要让 `namelist.input` 里的 `nproc_x * nproc_y` 等于 `NnodesATM`，ROMS `.in` 里的 `NtileI * NtileJ` 等于 `NnodesOCN`（见 [5.3](#53-processor-layout)）。

### 5.1. INLET_TEST Coupled

`Projects/Inlet_test/Coupled/coupling_inlet_test.in` 里 `NnodesWAV=1`、`NnodesOCN=1`，对应 **`mpirun -np 2`**。短时试跑可用 `timeout` 截断，确认耦合交换与写出文件后再做全长积分。完整算例为 `NTIMES=720`、`DT=60 s`（约 12 h 模式时间）。算例南边界封闭，北边界为正弦水位，SWAN 从北向南传入约 1 m 波高；网格和输入已在 `Projects/Inlet_test/Coupled`。

```bash
source /workspace/coawst-env.sh
cd /workspace/COAWST
timeout 240s mpirun -np 2 ./coawstM Projects/Inlet_test/Coupled/coupling_inlet_test.in \
  > /workspace/inlet_test_run.out 2>&1
```

验证主机上启动正常，ROMS 与 SWAN 开始交换场。240 s 后进程因 `timeout` 退出（exit 124），运行本身无报错；短跑大约到 timestep **254**（约 4.2 h 模式时间）。stdout 记录了进程划分（Ocean rank 0，Waves rank 1）、`ROMS version 4.3`（`mpif90` / gfortran，`MCT_LIB`，`SWAN_COUPLING`）、反复出现的 `SWAN grid 1 sent wave data to ROMS` / `ROMS … sent data to SWAN`（HSIGN / DEPTH / VEL 为有限值），以及写出的 `ocean_his_coupled.nc`、`ocean_avg_coupled.nc`、`ocean_sta.nc`、`PRINT01`。

完整积分去掉 `timeout`：

```bash
source /workspace/coawst-env.sh
cd /workspace/COAWST
mpirun -np 2 ./coawstM Projects/Inlet_test/Coupled/coupling_inlet_test.in
```

树里没有 `Projects/Inlet_test/Coupled/scrip_weights_inlet_test.nc`。同网格 Coupled 走 MCT 同网格路径，无需预生成权重文件。多网格或异网格时，v3.9 可以在运行期生成 SCRIP 权重，文件名由 `SCRIP_COAWST_NAME` 指定；文件已存在则复用。

PBS 机器上参照仓库里的 `run_coawst`，或手册里的 `run_nemo`，把 `mpirun` 和 `coupling_*.in` 写成作业脚本。SLURM 用 `sbatch` / `squeue`。

### 5.2. JOE_TC Coupled

`coupling_joe_tc.in` 里 `NnodesATM=1`、`NnodesWAV=1`、`NnodesOCN=1`，对应 **`mpirun -np 3`**。WRF 输入在 `Projects/JOE_TC/`（不在 `Coupled/`）：`namelist.input`、`wrfinput_d01`、`wrfbdy_d01`（`run_hours=120`，`time_step=25`，`nproc_x=nproc_y=1`）。ROMS 为 `NtileI=NtileJ=1`，`NTIMES=17280`，`DT=25 s`。验证时段为 2026-10-28（America/Los_Angeles，约 07:22–08:03）。

#### 5.2.1. 运行前准备（仓库根目录）

WRF 在运行目录查找 namelist、边界/初始场以及辐射与物理表文件。手册要求把 namelist / wrfinput / wrfbdy 拷到 `root_dir`，并把 `WRF/run` 下的表文件链到根目录：

```bash
cd /workspace/COAWST
cp Projects/JOE_TC/{namelist.input,wrfinput_d01,wrfbdy_d01} .
for f in WRF/run/*; do
  b=$(basename "$f")
  case $b in namelist*|*.exe|README*|CMake*|Makefile) ;; *)
    [ -e "$b" ] || ln -s "$f" "$b"
  ;; esac
done
```

#### 5.2.2. 必须设 big_endian

未设字节序时，WRF 进程立刻失败，报错为 `At line 6925 of file module_ra_rrtm.f90 (unit = 10, file = 'RRTM_DATA') Fortran runtime error: End of file`。

WRF 目标文件编译时带了 `-fconvert=big-endian`。gfortran 只在编译主程序时让这个转换生效；耦合主程序是 ROMS 的 `master.f90`，编译时没有该标志，运行期会按 little-endian 去读 big-endian 的 WRF 表文件，读到文件尾就报 EOF。运行前导出：

```bash
export GFORTRAN_CONVERT_UNIT=big_endian
```

永久修法是在 `Compilers/Linux-gfortran.mk` 的 `USE_WRF` 分支给 `FFLAGS` 加上 `-fconvert=big-endian -frecord-marker=4`，然后重编。验证主机未改 mk。也可以直接加载 helper：

```bash
source /workspace/coawst-env-joe_tc.sh
```

#### 5.2.3. 短时试跑

短时试跑可用 600 s 的 `timeout` 截断，并在 30 s 后发送 `SIGKILL`：

```bash
source /workspace/coawst-env-joe_tc.sh
cd /workspace/COAWST
timeout --kill-after=30s 600s mpirun -np 3 ./coawstM Projects/JOE_TC/Coupled/coupling_joe_tc.in \
  > /workspace/joe_tc_run.out 2>&1
```

验证主机上启动正常：Ocean / Waves / Atmos 分别在 rank 0 / 1 / 2。600 s 后进程因 `timeout` 退出（exit 124），运行无报错。WRF 推进到约 **2005-09-01_03:05:25**（约 3 h / 120 h），大约 1.25 s 墙钟对应 25 s 模式步。三向交换共 **19** 个耦合周期，12 类消息都出现过（例如 `WRF … sent data to ROMS`，以及 `SWAN … sent data to WRF` 和 `ROMS … sent data to SWAN`）。写出 `wrfout_d01_2005-09-01_00:00:00`（约 100 MB）、`ocean_avg.nc`、`ocean_dia.nc`、`ocean_rst.nc`；另有 `ocean_joe_tcs_his.nc`，mtime 异常，内容未核。

按这个速度，完整 **120 h** 在 3 个 rank 上大约要 **2 天**。增大 `NnodesATM` 时令 `nproc_x * nproc_y` 与它相等，并增大 `NtileI * NtileJ`，墙钟会缩短。完整积分去掉 `timeout`：

```bash
source /workspace/coawst-env-joe_tc.sh
cd /workspace/COAWST
mpirun -np 3 ./coawstM Projects/JOE_TC/Coupled/coupling_joe_tc.in
```

也可以改成 ExpA1（仅 WRF+SWAN）或 ExpA（仅 WRF+ROMS）。WRF–ROMS 耦合时建议 `sst_update = 1`，并设置 `io_form_auxinput4`。

### 5.3. Processor layout

耦合进程数由三层数字共同决定，三层必须对齐，否则 MPI 划分与模型内分解不一致：

| 层 | 来源 | 含义 |
|----|------|------|
| `NnodesATM` / `NnodesWAV` / `NnodesOCN` | `coupling_*.in` | 分给大气 / 波浪 / 海洋的 MPI 进程数；三者之和等于 `mpirun -np` |
| `nproc_x` / `nproc_y` | WRF `namelist.input` | WRF 域内分解；`nproc_x * nproc_y` 应等于 `NnodesATM` |
| `NtileI` / `NtileJ` | ROMS ocean `.in` | ROMS 瓦片分解；`NtileI * NtileJ` 应等于 `NnodesOCN` |

两次短跑的 `mpirun -np` 分别是 2 和 3：

| 算例 | `mpirun -np` | Nnodes* | WRF | ROMS |
|------|--------------|---------|-----|------|
| INLET_TEST Coupled | 2 | WAV=1, OCN=1 | （无） | （由 NnodesOCN 决定） |
| JOE_TC Coupled | 3 | ATM=1, WAV=1, OCN=1 | `nproc_x=nproc_y=1` | `NtileI=NtileJ=1` |

> **Note**
>
> 加大并行时同时改 `coupling_*.in`、WRF namelist 与 ROMS `.in`，再令 `mpirun -np` 等于新的 `Nnodes*` 之和。

## 6. Common pitfalls and recommended practices

下列失败点已在验证主机的部署与试跑中核对；编号不表示处理优先级。

1. **apt 不可用**（代理 `198.18.0.1` → 500/SSL）。处理：conda-forge 环境 `coawst`，外加 curl 装上的 `make` `.deb`。
2. **MCT `./configure` 无执行权限**。处理：`bash ./configure` 或 `chmod +x`。
3. **MCT 必须用与 COAWST 相同的 `mpif90`**，并导出 `MCT_INCDIR` / `MCT_LIBDIR`。否则常见 “module file was not generated by this compiler” 或找不到 `m_MCTWorld`。
4. **`COAWST_APPLICATION` 必须全大写**（`INLET_TEST`），与 `inlet_test.h` 对应；小写匹配会失败。
5. **发行版 `MY_ROOT_DIR` 是 Cygwin 路径** `/cygdrive/d/models/COAWST`，Linux 上必须改成实际路径（验证主机为 `/workspace/COAWST`）。
6. **发行版 `which_MPI=intel`**，本栈改为 `openmpi`。
7. **gfortran 15**：`-fallow-argument-mismatch` 已在 `Linux-gfortran.mk` 与 MCT configure 中；MPI 类型不匹配警告可忽略。
8. **`mpirun -np` = 各 `Nnodes*` 之和**（Inlet Coupled 为 2；JOE_TC Coupled 为 3）。
9. **`./build_coawst.sh -j 4` 可用**；若出现 `mpif.h` 竞态，改用不并行或 `-j 1`。
10. **耦合应用不要单独编 WRF**；由 `build_coawst.sh` 在启用 WRF 时统一处理。
11. **切换算例要重编**：改 header / 路径后清理或重建 `Build_roms` 及 WRF 产物。
12. **gfortran 的 mk 里不要留 Intel 专用选项**（如 `-assume byterecl`），旧树上会导致 SWAN/gfortran 失败。
13. **WRF configure 要 m4 / flex / bison**（conda-forge）；`./compile` 要 `/bin/csh`（可 `ln -sf …/tcsh /bin/csh`）。
14. **WRF configure 交互**：`printf '34\n1\n' | ./build_coawst.sh -j 4`（GNU dmpar + basic nesting）。
15. **JOE_TC 运行必须 `GFORTRAN_CONVERT_UNIT=big_endian`**，否则 `RRTM_DATA` EOF；用 `/workspace/coawst-env-joe_tc.sh`，不要写进默认 `coawst-env.sh`。
16. **JOE_TC 的 namelist / wrfinput / wrfbdy 在 `Projects/JOE_TC/`**，不在 `Coupled/`；跑前拷到根目录并 symlink `WRF/run` 表文件。
17. **部分重编标志**：`-noclean -nocleanwrf -nocleanswan` 可保留 `configure.wrf`；全量 clean 会删 `Build_roms`，且带 `-nocleanwrf` 时脚本会跳过 `mct_params`。

推荐做法：先用 INLET_TEST 验证 ROMS+SWAN+MCT 工具链，再编 JOE_TC；默认环境与含 WRF 环境分开（`coawst-env.sh` 与 `coawst-env-joe_tc.sh`）；换应用前备份 `coawstM` 与 `build_coawst.sh`（验证主机留有 `coawstM.inlet_test` / `coawstM.joe_tc`）；短跑用 `timeout` 截断，确认耦合交换与写出文件后再去掉 timeout 做全长积分。
